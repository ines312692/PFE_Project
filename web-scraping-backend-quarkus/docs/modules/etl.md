## ETL Module

### Purpose

The ETL module applies a configurable, ordered pipeline of cleaning, transformation and enrichment steps to the records of a scrape result, optionally saves the outcome as a new data version, produces a data quality report, and exports the resulting records to a file, a database, or a webhook.

### Endpoints

1. `POST /v1/scrape-results/{id}/etl`. Runs the configured ETL steps against a scrape result, or against a specific data version if `fromVersion` is given, and returns the transformed records together with a per step report and a quality report, without saving anything.
2. `POST /v1/scrape-results/{id}/etl/apply-and-save`. Same as the previous endpoint, but persists the outcome as a new data version.
3. `POST /v1/scrape-results/{id}/export`. Exports the records, optionally from a specific data version, to a chosen format and destination.
4. `GET /v1/exports/{exportId}/download`. Downloads a previously generated export file. Download links expire after fifteen minutes.

### ETL Step Types

1. `STRIP_HTML`. Strips HTML tags from string fields and collapses extra whitespace.
2. `TRIM_WHITESPACE`. Trims leading and trailing whitespace on all string fields.
3. `MISSING_VALUE_HANDLER`. Fills blank or null fields with a fallback value, or drops the record entirely when configured to do so.
4. `DEDUPLICATE`. Removes duplicate records based on a fingerprint of one or more key fields, or of the whole record if no keys are given.
5. `VALIDATE_FIELDS`. Validates records against a set of rules, either given explicitly, derived from an extraction schema, or inferred from the first record, checking required fields, types, regular expressions, numeric ranges, enumerations, and cross field constraints. This step produces the quality report described below, and does not remove any record.
6. `NORMALIZE_DATE`. Parses dates written in many common formats and rewrites them in ISO `yyyy-MM-dd` form, auto detecting date like field names when none are specified.
7. `NORMALIZE_PRICE`. Extracts a numeric price from a string, handling both comma and period decimal conventions, and reformats it with two decimal places.
8. `CAPITALIZE`. Changes the case of string fields, to title case, upper case, or lower case.
9. `NORMALIZE_ENUM`. Lowercases and snake cases enumeration like values, auto detecting fields such as status, type, category, state, kind or mode.
10. `ANONYMIZE_PII`. Detects and masks personal data such as email addresses, phone numbers, IBANs, credit card numbers, French social security numbers, and IPv4 addresses, using a full, partial, or hash based masking strategy, with support for including or excluding specific fields.
11. `PARSE_HTML`. Parses an HTML string field into multiple structured records, first trying table extraction, then repeated sibling block detection, then falling back to the page title and body text.
12. `AI_NER`. Uses an LLM to extract named entities such as persons, organizations, locations, dates and amounts.
13. `AI_CLASSIFY`. Uses an LLM to classify each record's text into one of a configurable set of labels, with a confidence score.
14. `AI_SUMMARIZE`. Uses an LLM to produce a short summary of a text field.
15. `AI_DETECT_ANOMALIES`. Uses an LLM to flag aberrant values, such as negative prices, future dates, or internally contradictory fields.

All AI backed steps cap the number of records they process, batch their calls, and retry on LLM rate limiting by slowing down and splitting batches. A batch that still fails is left unmodified rather than failing the whole pipeline.

Steps are discovered automatically and run in the order given in the request. A step that fails is recorded as an error for that step, and the pipeline continues with the remaining steps rather than aborting entirely.

### Data Quality Report

When a `VALIDATE_FIELDS` step runs, a quality report is produced alongside the transformed records. It includes the total, valid and invalid record counts and a validity rate, a per field breakdown of completeness and validity, and the ten most significant rule violations, each identified by record index, field, rule name, the offending value, and a human readable message.

### Export

1. Formats: CSV, JSON, an Excel workbook with a styled header and alternating row colors, Markdown with a front matter block, JSON-LD structured as a schema.org data feed, and an llms.txt style link list.
2. Destinations: a downloadable file, a PostgreSQL table created automatically if it does not exist, or a webhook that receives the records in configurable batches.
3. Download flow: exporting to a file stores the generated bytes in memory and returns a download URL valid for fifteen minutes. The download endpoint streams the file with the appropriate content type, and returns not found once the link has expired.
